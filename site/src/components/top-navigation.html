The second console shell. Sections live in a bar under the header and their menus open on click. The side navigation remains the default; this suits a console with a handful of sections rather than a deep one.

How it behaves

  • Click, never hover. Each section is a native disclosure element, so the menus open with JavaScript off. The shared console script closes an open menu on an outside press and on Escape, and returns focus to the section that opened it.
  • One menu at a time when scripting is available. Without it, more than one can be open, and the layout tolerates that.
  • The current section stays marked while its menu is shut, so an operator can always see where they are.
  • Nothing is hidden. Every destination stays reachable at every width, and a release gate compares what the bar can reach against the drawer, which is rendered from the same definition.
  • Phones use the drawer. Below 900px the bar steps aside and the drawer from the side-navigation shell takes over, so there is one phone navigation in the kit.

Markup

A console opts in with adminwrap--topnav, which hides the side column at desktop width. The strip sits between the header and the console body, and the drawer markup stays in place for phone widths.

Which shell to choose

  • Use the side navigation when a console has many top-level areas. A rail shows them all at once, and a bar would push most of them behind menus.
  • Use the top navigation when a console has a handful of sections, up to about nine, each holding a short menu, and the horizontal bar reads as the product's spine.
  • Both shells use the same navigation definition, the same header with the account menu last, and the same drawer on phones, so moving between them is a shell change rather than a rebuild.
