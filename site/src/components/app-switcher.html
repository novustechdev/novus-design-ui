One switcher for every Novus console, after the Microsoft 365 app launcher: a nine-dot button at the far left of the header opens a panel with a search field and a grid of the apps the signed-in person may open. It reads the workspace launcher's catalog at run time, so an app added to the workspace reaches every console without a rebuild.

Full-page demos, each with a viewer picker: side-navigation shell and top-navigation shell.

How it behaves

  • First in the header. Nothing sits to the left of the switcher, in either shell. On a phone the drawer toggle follows it, then the product lockup. A console draws one grid button, never two, and the layout audit fails a header that places anything before it.
  • Search first. The field takes focus when the panel opens and filters by name, description and category as you type. When nothing matches it says so in words.
  • Tiles. Each tile is the product's mark with its name under it, and the description as its tooltip and accessible description. Five to a row on a desktop, four on a tablet, three on a phone. This console's own tile is marked as current and goes nowhere.
  • Order. The last four apps this console's switcher opened come first, then the catalog's category order, then catalog order.
  • All apps is the last tile whenever a workspace launcher is declared, and opens it, where every app is grouped by category and can be pinned.
  • Keyboard. The arrows walk the grid as drawn, Home and End jump to its ends, typing goes to the search field, Tab stays inside the panel, and Escape closes it and returns focus to the button. A press outside closes it too.
  • Same tab. Every app signs in through the same realm, so a second tab would only be a second copy of the session.

Who sees what

  • An app shows when one of its requiredRoles is among the claims the console hands over: the viewer's realm roles and group names. An entry with no roles, a malformed entry, or a viewer with no claims shows nothing.
  • Only https addresses on the allowed host suffixes are linked (by default .novustech.dev and .novustech.id). Any other entry is dropped, so a tampered catalog cannot send an operator to a look-alike host.
  • The catalog is fetched when the panel first opens, never at page load, and is given three seconds. If it does not answer, or answers something unreadable, the switcher uses the last good copy this browser kept, then the deployment's static list, then only "All apps". The page never waits on it.
  • A bank's own deployment, whose staff do not sign in to the Novus workspace, declares no launcher: its switcher shows the static list and no "All apps" tile.

Markup

Load js/novus-app-marks.js and js/novus-app-switcher.js with console.css, as plain scripts or as imports from a bundler, and place the element first in .appheader__left.

NameKindMeaning
currentattributeThis console's app id. Its tile shows as current.
launcherattributeThe workspace launcher's origin, such as https://workspace.novustech.dev. Leave it out on a bank's own deployment.
catalogattributeThe catalog's address, when it is not {launcher}/api/catalog.
allowed-hostsattributeHost suffixes an app may live on, separated by spaces. A leading dot admits subdomains only.
fallbackattributeBase64 JSON of the deployment's static list, [{key, name, url}]: the apps setting consoles carry today.
labelsattribute (JSON) or property (object)The element's own words in the console's language: apps, find, grid, all, allTitle, noMatch, noApps, loading, countOne, countOther (with {n} for the number). A key left out keeps its English; every label is set as text.
claimspropertyThe viewer's realm roles and group names, as an array of strings.
novus-app-openeventFired before the browser navigates, with the app id as its detail. It bubbles and is cancelable, so a host can keep the navigation for itself.
 
<!-- A plain-script console -->
<novus-app-switcher current="novatrace" launcher="https://workspace.novustech.dev"></novus-app-switcher>
<script>document.querySelector("novus-app-switcher").claims = session.roles.concat(session.groups);</script>

// A React console: attributes in JSX, the claims property set through a ref
import "novus-design-kit/js/novus-app-marks.js";
import "novus-design-kit/js/novus-app-switcher.js";
const ref = useRef(null);
useEffect(() => { ref.current.claims = [...roles, ...groups]; }, [roles, groups]);
<novus-app-switcher ref={ref} current="novabank" launcher={launcherOrigin} fallback={apps} />

The catalog

The workspace launcher answers GET /api/catalog with CORS open to any origin, no credentials and a five-minute cache. It holds names, addresses, categories and role names, and nothing secret.

{ "version": 1,
  "categories": [{ "id": "core-banking", "name": "Core banking" }],
  "apps": [{ "id": "novabank", "name": "NovaBank", "description": "Core-banking console",
             "category": "core-banking", "url": "https://novabank.novustech.dev",
             "mark": { "colour": "(the product colour)", "glyph": "novabank" },
             "requiredRoles": ["operator", "checker", "administrator"] }] }

Product marks

Each glyph names a mark in js/novus-app-marks.js: a square of the product's colour with a white line glyph, 24 units, stroke 1.8, round caps. The colours are fixed product identity, taken from the palette in tokens.css, and keep in the dark theme. The same marks ship as placed assets in logos/marks/. NovaMerchant's three marks share NovaMerchant's colour and are told apart by glyph. An app with no mark shows its initial on grey.
