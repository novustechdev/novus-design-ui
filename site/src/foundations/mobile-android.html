Android foundations

The Novus design system mapped onto native Android the way the Android team builds: Material 3 as published at m3.material.io, through Material Components for Android (the View system: XML themes, styles, and resources). Every value below is taken from tokens.css (rem converts at 16px per rem to dp/sp), so web and mobile share one source of truth; the build rejects any colour on this page that is not a token value.

Design mapping, not a run-verified guide: this page maps tokens onto Material 3 color roles and names its targets (com.google.android.material:material 1.14.x, Theme.Material3, AppCompat 1.7.x). Verification is the token-parity gate plus review, per constitution Principle VIII.

Color resources

Define the palette once in res/values/colors.xml, override in res/values-night/colors.xml: the resource system is the platform's own light/dark switch, mirroring the web tokens' dark block.

Typography: Carlito only

Bundle Carlito 400 and 700 in res/font/ (TTF from the design system master or Google Fonts; this npm package ships woff2 for the web only), declare the family, and map the kit type scale (sp respects platform font scaling; never disable it).

<!-- res/font/carlito.xml -->
<font-family xmlns:app="http://schemas.android.com/apk/res-auto">
    <font app:fontStyle="normal" app:fontWeight="400" app:font="@font/carlito_regular"/>
    <font app:fontStyle="normal" app:fontWeight="700" app:font="@font/carlito_bold"/>
</font-family>

<!-- the kit type scale, rem times 16 = sp: 2xl 30, xl 24, lg 20, md 18, base 16, sm 14, xs 12 -->
<style name="TextAppearance.Novus.Headline" parent="TextAppearance.Material3.HeadlineSmall">
    <item name="fontFamily">@font/carlito</item>
    <item name="android:textSize">24sp</item>   <!-- text-xl -->
    <item name="android:textStyle">bold</item>
</style>
<style name="TextAppearance.Novus.Body" parent="TextAppearance.Material3.BodyLarge">
    <item name="fontFamily">@font/carlito</item>
    <item name="android:textSize">16sp</item>   <!-- text-base -->
</style>

Dark mode: dual trigger, same as the web

DayNight plus the resource system follows the OS; a persisted in-app override is the second trigger, matching the web kit's toggle.

// persist "system" | "light" | "dark" (SharedPreferences or DataStore)
fun applyThemePref(pref: String) = AppCompatDelegate.setDefaultNightMode(
    when (pref) {
        "light" -> AppCompatDelegate.MODE_NIGHT_NO
        "dark"  -> AppCompatDelegate.MODE_NIGHT_YES
        else    -> AppCompatDelegate.MODE_NIGHT_FOLLOW_SYSTEM
    }
)

Rules that carry over unchanged

  • White (or near-black) ground, no gradients, elevation as a 1dp outline over shadow.
  • One accent per view; success and warning only where a judgement exists; risk messages always red; amounts always neutral.
  • Product names lowercase and solid-set (novapay); logos are placed assets from logos/ (drawable imports), never redrawn or typed.
  • Touch targets 44dp minimum; test at small-phone width first.
